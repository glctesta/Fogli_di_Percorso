# Fogli di Percorso — Piano 3.1: Workflow DRAFT / SUBMITTED

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task.

**Goal:** Estendere il Piano 3 introducendo lo stato `DRAFT` / `SUBMITTED` su `PathTracks`. Permettere all'utente di lavorare in modo incrementale su una bozza (in qualsiasi momento del mese corrente o precedente) e inviarla solo nella finestra 1-5 del mese successivo, momento in cui viene consumato il `RegistryId` tramite SP.

**Architecture:** Aggiunta colonna `Status CHAR(10) NOT NULL DEFAULT 'DRAFT'` + `SubmittedOn DATETIME NULL` su `fdp.PathTracks`. `PathTrackService` separa `create_draft_*` (no SP call, RegistryId NULL) da `submit(path_track_id)` (chiama SP, set Status='SUBMITTED'). Routes: nuovo `POST /pathtracks/<id>/update` per editare la bozza, nuovo `POST /pathtracks/<id>/submit` per confermare.

**Tech Stack:** Stesso del Piano 3 (Flask, pyodbc, freezegun).

**Riferimento spec:** sezione 6.3 (flow), 7.1 (calcolo), 7.2 (validazioni) + nuova sezione 7.7 da aggiungere al design doc.

**Prerequisito:** Piano 3 completato e taggato `v0.3.0-pathtracks`.

## Regole di business definitive

| Aspetto | Regola |
|---|---|
| **Stati ammessi** | `DRAFT` (default), `SUBMITTED` |
| **Creazione bozza** | In qualsiasi momento, per **mese corrente** o **mese precedente non ancora inviato** |
| **Modifica bozza** | Solo se `Status='DRAFT'` E (mese corrente OPPURE oggi <= 5 del mese successivo al mese di riferimento) |
| **Cancellazione bozza** | Solo se `Status='DRAFT'`. Soft delete con DateOut |
| **Submit (invio)** | Solo se `Status='DRAFT'` E oggi è nella finestra `[1, 5]` del mese successivo a `DatePathTrack` |
| **RegistryId** | Generato via SP `Employee.dbo.Registro` **al momento del submit** (non alla creazione draft) |
| **`SubmittedOn`** | Valorizzato a `GETDATE()` al submit. NULL per bozze |
| **Dopo submit** | Record immutabile dall'utente. `ReceivedOn` resterà NULL (sarà popolato da sistema esterno) |
| **Bozza dopo il 5** | Resta in `DRAFT` ma read-only. Admin (Piano 4) potrà sbloccare/inviare manualmente |
| **Stato di default** | `DRAFT` (la migrazione assegna 'SUBMITTED' alle righe esistenti che hanno RegistryId, per retro-compatibilità) |

## Task

### Task 1: DDL migration `002_add_status.sql`

**Files:** Create `sql/002_add_status.sql`

```sql
USE Employee;
GO

-- ---------------------------------------------------------------------
-- Aggiunge Status e SubmittedOn a fdp.PathTracks per workflow DRAFT/SUBMITTED
-- ---------------------------------------------------------------------
IF NOT EXISTS (
    SELECT 1 FROM sys.columns
    WHERE Name = N'Status'
      AND Object_ID = Object_ID(N'fdp.PathTracks')
)
BEGIN
    ALTER TABLE fdp.PathTracks
        ADD Status      CHAR(10)  NOT NULL CONSTRAINT DF_PathTracks_Status DEFAULT 'DRAFT',
            SubmittedOn DATETIME  NULL;
END
GO

-- Retro-compat: i record esistenti che hanno RegistryId valorizzato
-- vengono considerati gia' SUBMITTED.
UPDATE fdp.PathTracks
SET Status = 'SUBMITTED',
    SubmittedOn = COALESCE(SubmittedOn, DateSys)
WHERE Status = 'DRAFT'
  AND RegistryId IS NOT NULL;
GO

-- Index per le query "le mie bozze"
IF NOT EXISTS (
    SELECT 1 FROM sys.indexes
    WHERE name = N'IX_PathTracks_Emp_Status'
      AND object_id = OBJECT_ID(N'fdp.PathTracks')
)
BEGIN
    CREATE INDEX IX_PathTracks_Emp_Status
        ON fdp.PathTracks (EmployeeHireHistoryId, Status)
        WHERE DateOut IS NULL;
END
GO

PRINT 'Migrazione 002_add_status.sql completata.';
```

### Task 3: Estendere `DeadlineService` con helper specifici

**File:** `fdp_app/pathtracks/deadline.py`

Aggiungere:

```python
def can_create_draft_for(date_path_track: date) -> bool:
    """True se posso creare/modificare una bozza per quel mese.
    Mese ammesso: corrente o precedente; modifica precedente solo entro il 5 del successivo."""
    now = datetime.now(_TZ).date()
    current_month = now.replace(day=1)
    if date_path_track == current_month:
        return True  # mese corrente sempre OK
    previous = (current_month - relativedelta(months=1))
    if date_path_track == previous:
        # mese precedente OK solo finche' siamo entro il 5 del mese corrente
        deadline_day = current_month.replace(day=5)
        return now <= deadline_day
    return False


def can_submit_for(date_path_track: date) -> bool:
    """Alias di is_open_for_month: submit solo nella finestra 1-5 del mese successivo."""
    return is_open_for_month(date_path_track)
```

- `can_submit_for` identico a `is_open_for_month`

```markdown
### 7.7 Workflow DRAFT / SUBMITTED

Ogni `PathTracks` ha un campo `Status` con due valori:
- `DRAFT`: bozza modificabile. RegistryId NULL.
- `SUBMITTED`: dichiarazione confermata. RegistryId valorizzato. SubmittedOn = momento di invio.

Regole:
1. Bozza creabile/modificabile per mese corrente sempre; per mese precedente solo fino al 5 del successivo.
2. Submit possibile solo nella finestra 1-5 del mese successivo a DatePathTrack. Genera RegistryId via SP.
3. Dopo submit il record e' immutabile dall'utente.
4. Bozza non inviata entro il 5 resta DRAFT ma read-only; admin (Piano 4) puo' sbloccarla.
```
